# Техническое задание (ПР № 2, актуализируется по мере развития проекта)

## 1. Наименование системы

Информационная система управления данными зарядной инфраструктуры электромобилей с интеграцией метеорологических данных «EV Charge Advisor CH» (Система).

## 2. Назначение

Поддержка водителей при выборе зарядной станции, аналитиков — при оценке и планировании загрузки сети, инженеров данных — при контроле поступления и качества данных. Назначение согласовано с [ПР № 1](pr1_analysis.md).

## 3. Характеристика предметной области

1. **Объекты:** кантон, почтовый индекс, оператор, станция, зарядная точка (EVSE), тип разъёма, автомобиль, статус точки, погода, запрос рекомендации.
2. **Участники:** водитель, аналитик, инженер данных; внешние системы — BFE (data.geo.admin.ch), архив статусов на GitHub, Open-Meteo, Open EV Data, swisstopo.
3. **Операции:** загрузка и обновление справочников, фиксация статусов, расчёт загрузки, прогноз, подбор станций, проверка качества, просмотр дашбордов.
4. **Информационные потоки:** источник → загрузчик → raw-файл → staging → core → mart → дашборд или рекомендация; журнал загрузок и результаты проверок пишутся в ops.
5. **Существенные ограничения:** бизнес-правила 1–10 ПР № 1.

## 4. Пользователи и роли

| Роль | Задачи | Операции | Ограничения |
|---|---|---|---|
| Водитель | Подбор станции | Чтение справочников и статусов, вызов функции подбора, запись журнала запросов | Нет записи в справочники, нет доступа к ops и процедурам загрузки |
| Аналитик | Анализ загрузки и прогнозов | Чтение витрин и справочников | Только чтение |
| Инженер данных | Загрузка, преобразования, качество | Чтение и запись stg, core, mart; запись ops; вызов процедур | Не изменяет журнал версий схемы, не удаляет журнал загрузок |
| Администратор | Сопровождение схемы | Миграции, роли | — |

## 8. Ограничения и допущения

**Ограничения предметной области:** источник статусов отдаёт только текущий срез без истории; у части точек нет мощности или координат; идентификаторы точек некоторых операторов менялись между 2024 и 2026 гг.

**Технические ограничения:** всё работает локально на одном ПК (Python 3.12, PostgreSQL 17, DuckDB); облачные сервисы не используются; архив (~3 млрд строк) обрабатывается частями при ограниченной памяти.

**Допущения:** архив статусов 2024–2025 гг. представителен для поведения сети в 2026 г.; точки одной станции занимаются независимо (проверяется калибровкой); время в пути оценивается по прямой с коэффициентом 1,3, если OSRM не запущен.

## 9. Ожидаемый результат

Единый программно-информационный комплекс, развёртываемый по README:
- база PostgreSQL со слоями и серверной логикой;
- загрузчики шести источников;
- обработка архива;
- модели прогноза;
- веб-приложение с рекомендателем, двумя дашбордами и страницей происхождения данных;
- тесты и CI.

## 10. Критерии приёмки

1. `scripts\init_db.ps1` и `evadvisor db migrate` создают БД без ошибок, повторный запуск тоже проходит без ошибок.
2. `evadvisor ingest all` загружает все источники; повторный запуск завершается без дублей.
3. `pytest` проходит полностью, включая сценарии доступа ролей.
4. Пользователь `app_driver` может вызвать подбор станций и не может изменить справочник точек.
5. Для Tesla Model 3 у вокзала Берна страница `/` выдаёт 5 станций с CCS или Type 2 и пояснением.
6. Страницы `/analytics` и `/operations` отображают данные из витрин, фильтры меняют результат.
7. Страница `/lineage` показывает цепочку от показателя «загрузка» до источника «архив статусов».
